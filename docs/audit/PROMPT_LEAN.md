## 1. Один раунд = один сеанс
- Сеанс выполняет **один** раунд (текущий — по `docs/audit/STATUS.md`) и в конце **останавливается**. Следующий раунд владелец запустит в новом сеансе той же фразой.
- Если контекст сжался посреди раунда — перечитай этот файл, `STATUS.md` и `roundN/GOALS.md`, продолжай с «Следующего шага». Не перечитывай историю раундов, REPORT, LOG, старые VERIFY.
- Работай автономно, без вопросов (правила безопасности 0.3 старого файла действуют полностью).

## 2. Чтение кода — экономно
- Ищи `grep -n` / `rg`, читай нужные функции по диапазону строк, а не файлы целиком. Один раз прочитанное не перечитывай — помни.
- Не открывай большие сгенерированные/vendor-файлы (`styles.css`, `static/vendor/*`, `*.min.js`, lock-файлы), логи, скриншоты.
- Из документации читай только `CLAUDE.md`, `STATUS.md`, текущий `GOALS.md` и нужный кусок старого промпта.

## 3. Тесты — пачками, а не после каждой правки
- **Во время работы над частью:** только тесты изменённого модуля и acceptance-тесты этой части:
  `../venv/Scripts/python.exe -m pytest -q -x tests/<файлы> 2>&1 | tail -n 15` (из `ai_manager/`). Вывод — всегда через `tail`, в контекст не тянуть простыни.
- **В конце части** (D, E, API, F…): один прогон быстрого набора `-m "not e2e and not responsive" -q 2>&1 | tail -n 20`. Красное — чинить сразу.
- **e2e и responsive** — во время работы только для изменённых страниц и на 3 ширинах (`-k "375 or 1024 or 1440"` или аналог); **полный** e2e + responsive на 11 ширинах — **один раз в конце раунда**, запускать в фоне (`run_in_background`) и параллельно делать документацию.
- Логику с риском (запись в хранилище, права, токены, агент, очередь/идемпотентность) — по-прежнему тесты **до** кода. Для простого UI — тест можно писать вместе с кодом.
- Acceptance-тесты Round 4 уже написаны (77 xfail) — не переписывать; снимать `xfail` по мере выполнения целей. Для Round 5 писать компактно: 1 тест на цель/кластер критериев, без дублирования unit-тестов.
- Запрет ослаблять/удалять acceptance-тесты ради прохождения — действует.

## 4. Проверка агентом — одна за раунд, ограниченная
- В конце раунда, после зелёного быстрого набора, **один** независимый агент-ревьюер в фоне. Бриф ему (коротко): diff раунда (`git diff <начало раунда>..HEAD --stat` + ключевые файлы), список целей из GOALS, фокус — безопасность записи в хранилище, права токенов, данные не теряются/не удаляются, пути не выходят за хранилище; **не более 5 мутаций** в самых рискованных местах; не запускать полный e2e (это делает основной агент); отчёт ≤ 60 строк в `docs/audit/roundN/VERIFY.md`: только находки с уровнем (HIGH/MEDIUM/LOW) и файлом:строкой.
- Пока ревьюер работает — основной агент делает полный e2e/responsive в фоне и пишет документацию раунда, затем готовит **GOALS.md и acceptance-тесты следующего раунда** (с `xfail`), чтобы следующий сеанс сразу начал с кода.
- Исправить HIGH и MEDIUM (с регрессионным тестом), LOW — по усмотрению (записать в REPORT, что оставлено). **Второй круг проверки — только если были HIGH**, и только перепроверка этих находок тем же коротким брифом.
- Отдельные верификаторы вёрстки, повторные «финальные аудиты», мутационное тестирование всего подряд — **не делать**.

## 5. Журнал — минимум
- `STATUS.md` — **перезаписывать** (не дописывать), ≤ 12 строк: текущий раунд, сделанные части, «Следующий шаг: …». Обновлять после каждой части.
- `LOG.md` — одна запись на **часть** (≤ 4 строки: что сделано, тесты N passed, коммит) + отдельная запись только на HIGH-баг.
- `DECISIONS.md` — только реальные развилки, ≤ 3 строки на решение (варианты → выбор → почему).
- `docs/BUGS.md` — одна строка на баг: id, суть, тест-регрессия.
- В чат вывод тестов не вставлять — только итог «N passed / M failed». Полный финальный прогон — в `docs/audit/roundN/test-run.txt`.
- Скриншоты — только в конце Round 5 и только изменённые страницы.

## 6. Коммиты
