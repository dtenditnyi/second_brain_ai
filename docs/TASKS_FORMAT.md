# Формат заметки задач (контракт для сайта и Telegram-бота)

Все задачи сайта хранятся в **одной заметке** хранилища Obsidian. Сайт читает задачи оттуда и
записывает изменения обратно (commit + push). Правки, сделанные в Obsidian на ПК или телефоне,
появляются на сайте после синхронизации. Бот (Round 4) **сам в git не пишет**: он работает только
через API сайта, а сайт — единственный писатель в хранилище.

Реализация: `ai_manager/core/tasks_md.py` (чистый модуль без Django: разбор и сериализация без
потерь), `core/vault_writer.py` (единый механизм записи), `core/tasks_service.py` (кэш, очередь).

## 1. Где лежит заметка

- По умолчанию: `01 - Projects/🎯 Цели и планы/Задачи.md`.
- Глобально путь меняется переменной `TASKS_NOTE_PATH` в `.env`. Каждый пользователь может задать
  свой путь в «Настройках» (поле «Заметка задач»).
- Путь всегда относительный и находится внутри хранилища. Пути с `..`, абсолютные пути, `.git/` и
  `.obsidian/` запрещены.
- Если заметки нет, сайт создаёт её при первой записи:

```markdown
---
tags: [planning]
type: tasks-db
status: active
date: 2026-11-11
aliases: [Задачи, Tasks]
---
# 🎯 Задачи

> [!info] Задачи сайта Second Brain
> Одна строка — одна задача. Сайт и бот меняют только строки задач, остальной текст не трогают.

## 📥 Входящие

## 🔥 Срочно

## ✅ Выполнено

🔗 [[Главная (Home)]]
```

## 2. Строка задачи

Одна задача — одна строка-чекбокс. Формат совместим с Dataview и плагином Tasks:

```markdown
- [ ] Сдать лабу по физике 📅 2026-11-14 ⏫ #university ➕ 2026-11-11 🆔 t7k2m9
```

Порядок полей, в котором пишет сайт: текст → `📅` срок → приоритет → теги → `➕` дата создания →
`✅` дата выполнения → неизвестные поля → `🆔` ID. При чтении порядок не важен.

| Элемент | Значение |
|---|---|
| `- [ ]` | статус **todo** (к выполнению) |
| `- [/]` | **in progress** (в процессе) |
| `- [x]` | **done** (выполнено); сайт добавляет `✅ ГГГГ-ММ-ДД` |
| `- [-]` | **cancelled** (отменено); сайт добавляет `❌ ГГГГ-ММ-ДД` |
| `- [>]` | **forwarded** (перенесено, используется для недельных заметок) |
| `📅 2026-11-14` | срок |
| `🔺` / `⏫` / `🔼` / `🔽` | приоритет: срочный / высокий / средний / низкий (`⏬` читается как низкий). Нет значка — обычный приоритет, сайт его не добавляет |
| `#university` | теги — **только** из разрешённого списка (ниже); остальные сайт не принимает |
| `➕ 2026-11-11` | дата создания (ставит сайт) |
| `🆔 t7k2m9` | стабильный уникальный ID: 6 символов `a-z0-9` |

Разрешённые теги: university, dsa, physics, databases, economics, electronics, romanian, nuclear, dev,
ai, homelab, driving, cooking, sport, health, finance, planning, games, books, personal, obsidian.

## 3. ID

- Сайт ссылается на задачи только по `🆔`.
- Строкам без ID (например, задачам, добавленным вручную в Obsidian) сайт добавляет ID при
  следующей записи. Повторяющиеся ID исправляются так: первая строка сохраняет ID, остальные
  получают новые.
- Пока у строки нет ID, сайт показывает её и узнаёт по точному тексту строки.

## 4. Разделы

- Заголовки (`## 📥 Входящие`, `## 🔥 Срочно`, `## ✅ Выполнено` и любые свои) нужны только для
  порядка. **Статус задачи определяется символом в чекбоксе, а не разделом.**
- Новые задачи по умолчанию попадают в «📥 Входящие» (после последней задачи раздела). Если такого
  раздела нет, сайт создаёт его перед строкой `🔗 [[…]]` внизу заметки.
- Сайт не переносит задачи между разделами сам: выполненная задача остаётся на своём месте, чтобы
  изменения были минимальными. Переносить можно вручную в Obsidian.

## 5. Что сохраняется байт в байт

- Весь текст, который не является задачей: frontmatter, абзацы, callouts, таблицы, блоки Dataview и
  код (внутри блоков ``` задачи не распознаются), подзадачи с отступом.
- Строки задач, которые операция не меняет, остаются нетронутыми, включая окончания строк
  (LF/CRLF), отступы, эмодзи и кириллицу.
- В изменённой строке неизвестные поля (`⏳ дата`, `🛫 дата`, `🔁 every week`, `⛔ …` и прочие)
  сохраняются и ставятся перед `🆔`.

## 6. Операции (для API и бота)

| Операция | Поля |
|---|---|
| `add` | `text` (обязательно), `due`, `priority` (`urgent`/`high`/`medium`/`low`), `tags` (список), `status`, `section` |
| `update` | `id` + любые из `text`, `due` (`null` удаляет срок), `priority` (`null` удаляет), `tags`, `status` |
| `delete` | `id` |

- Каждая операция применяется к **свежей** версии заметки: блокировка → `pull` → операция → commit
  от автора «Second Brain» с сообщением `tasks: …` → `push`.
- Если `push` отклонён (кто-то успел изменить хранилище), сайт заново делает `pull` и повторно
  применяет ту же операцию (а не перезаписывает файл) — до 4 попыток.
- Если задачу удалили в другом месте, сайт показывает: «Задача была удалена или изменена в Obsidian —
  список обновлён».
- Если GitHub недоступен, операция встаёт в очередь (outbox), задача сразу видна с пометкой
  «не синхронизировано». Очередь отправляется в исходном порядке при следующей успешной
  синхронизации.
- Если у токена нет права записи, сайт показывает ошибку «Contents: Read and write» — нужен PAT с
  этим доступом к репозиторию хранилища.

## 7. Синхронизация

- Страницы «Задачи» и «Главная» перечитывают заметку, если с прошлой синхронизации прошло больше
  `TASKS_SYNC_INTERVAL` секунд (по умолчанию 60). Кнопка «Обновить» синхронизирует сразу.
- `python manage.py sync_tasks --all` делает то же для всех пользователей; в проде её каждые
  `TASKS_SYNC_INTERVAL` секунд запускает сервис `scheduler` из docker-compose.
- Старые задачи из базы сайта переносятся командой
  `python manage.py export_tasks_to_note --user ИМЯ [--dry-run]`. Повторный запуск дублей не создаёт.
